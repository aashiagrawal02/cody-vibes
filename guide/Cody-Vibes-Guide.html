Part 1

How to use Cody Vibes

Follow this once on your own before the presentation. Use two screens, for example your laptop and your phone, or a normal window and an incognito window. That way you can see the collaboration happen live.

Start the app

Open the Terminal, go to the project folder, and pick one of the two ways below. You only need npm install the very first time.

cd "/Users/mac/Desktop/mini project"
npm install
With internet · recommended

Public link for any device

npm run share
  1. Wait about 10 seconds for the box that says Public link.
  2. Copy the https://….trycloudflare.com link and open it.
  3. Keep the Terminal open and your laptop awake. Closing it ends the link.

Each run gives a new link, so start it again just before class.

No internet · backup

Local only, on this laptop

npm start
  1. Open http://localhost:3000.
  2. For a second user, open an incognito window at the same address.
  3. Friends on the same Wi-Fi can use http://<your-ip>:3000. Find the IP with ipconfig getifaddr en0.

Step-by-step demo

These are real screenshots. “Rahul” is the host on the laptop and “Priya” is a friend on another device. Under each step is a line you can say out loud while you do it.

  1. Open the link and sign up

    • Click Sign up, choose a username (3–20 letters or numbers) and a password (6+ characters).
    • The Invite code box is optional. Leave it empty.
    • Click Create account. You land on your dashboard.

    SayEvery user has an account. Passwords are never stored as plain text; they are hashed with bcrypt.

  2. Create a coding room

    • Under Create a room, type a name such as DSA Practice.
    • Pick a template: JavaScript, Python, C, C++, Java, Ruby, or Web (HTML/CSS/JS).
    • Click Create room. Starter files are created for you.

    SayA room is a shared project. Each one gets a short code like cbm-x9u-2f2.

  3. Invite a friend

    • In the room, click Invite at the top right.
    • Click Copy link, or Copy invite message, or WhatsApp.
    • Your friend opens the link, signs up or logs in, and goes straight into this room.
    • They can also type the room code into Join a room on their dashboard.

    SaySharing is one click. The link already points to the right room.

  4. Code together in real time

    • Both of you type in the same file. Every keystroke appears on the other screen almost instantly.
    • Each person's cursor shows in their own colour with their name above it.
    • Online on the left shows who is here and which file they are editing.
    • Coloured dots next to a file name mean someone else is in that file.

    SayEven if we type on the same line at the same moment, nothing gets lost. That is handled by a CRDT called Yjs.

  5. Run the code, with input

    • If the program asks for input, click Input (stdin) and type it, for example a name.
    • Click Run or press Ctrl/⌘ + Enter.
    • Output appears in the Console for everyone in the room, with who ran it and how long it took.
    • The button turns into Stop while a program runs. Programs are stopped after 10 seconds.

    SayThe server compiles and runs the code, then streams the output to everyone in the room.

  6. Chat while you code

    • Open the Chat tab. A pink badge shows unread messages.
    • Messages are saved, so people who join later can read the history.
    • The chat also shows when someone joins or leaves.

    SayThe team can discuss without switching to another app.

  7. Build a web page with live preview

    • Create a room with the Web (HTML/CSS/JS) template.
    • Open the Preview tab. It updates about half a second after anyone types.
    • Click Open in tab to see the page full size.

    SayI can change the CSS and my friend sees the website change at the same time.

Other features worth showing

Multiple files

Click ＋ next to Files to add one. Double-click a name to rename it, or hover and click the bin to delete. Files can import each other, for example from helpers import fib.

Auto-save

There is no Save button. Everything is saved within about a second and is still there after the server restarts.

Download as ZIP

Click Download in the room, or on the dashboard card, to get every file in the room as a .zip.

Rename or delete a room

The owner can click the room name to rename it. On the dashboard, owners can delete a room and members can leave it.

Reconnects by itself

If Wi-Fi drops, the status pill shows Reconnecting…. Anything typed meanwhile is merged when it comes back.

Works on phones

The layout stacks into one column on a phone, so a friend can join from their mobile.

How it works, in simple words

Real-time sync · Yjs (CRDT)

Why edits never clash

Each room is a Yjs document. When you type, Yjs creates a tiny update describing only that change, not the whole file. Every browser applies the updates, and the CRDT maths guarantees that all copies end up identical, whatever order the updates arrive in.

Simple version: like Google Docs, every letter has its own ID, so two people can type at the same spot without overwriting each other.

Connection · WebSocket via Socket.IO

Why updates are instant

Normal web requests only go from browser to server. A WebSocket keeps a connection open, so the server can push changes to everyone the moment they happen. Socket.IO also reconnects automatically.

Simple version: a phone call that stays connected, instead of sending letters.

Presence · Yjs awareness

How cursors and names appear

Each browser shares a small “awareness” state: your name, colour, cursor position, and the file you have open. It isn't saved, and it disappears when you leave.

Simple version: a live “who's here and where” board.

Execution · child processes

How Run works

The server writes the room's files into a temporary folder and starts the right program (python3, g++, node…). It passes in your input and streams the output back to the room. The program is killed after 10 seconds or 200 KB of output, and the folder is deleted.

Simple version: the server is the computer that runs everyone's code.

Security · bcrypt + JWT

How login stays safe

Passwords are hashed with bcrypt, so even we can't read them. After login, the server gives the browser a signed token (JWT) in an httpOnly cookie, valid for 30 days. Page scripts can't steal it.

Simple version: a tamper-proof entry pass.

Storage · JSON file + binary docs

Where data is kept

Users, rooms and chat are in data/db.json. Each room's code is saved as a compact Yjs file in data/docs/. Saves are written atomically, to a temp file first and then renamed, so a crash can't leave a half-written file.

Simple version: no database server to install, so it runs anywhere with Node.js.

Viva questions and answers

Read these aloud a few times. Answer in your own words, since teachers can tell when an answer is memorised.

Q1What is your project, in one or two lines?

Cody Vibes is a real-time collaborative coding platform. Several people can write code in the same files at the same time from their browsers, see each other's cursors, run the program, and chat, without installing anything.

Q2Why not just send the whole file every time someone types?

If two people type at once, each would send their own full version, and whoever arrives last would overwrite the other person's work. It also wastes bandwidth. With Yjs, only the small change is sent, for example “insert ‘a’ after character X”. Changes from different people merge automatically.

Q3What is a CRDT?

CRDT stands for Conflict-free Replicated Data Type. It is a data structure that can be copied to many computers and edited independently, and is guaranteed to end up the same everywhere once all changes are shared. There is no central “lock” and no lost edits. Yjs is a popular CRDT library for text.

Q4What happens if two people type on the same line at the same moment?

Both edits are kept. Every character has a unique ID made of the user's ID and a counter, so Yjs can always place each character in a consistent order. Every screen shows the same final text. I tested this with two users inserting at the same position at the same time.

Q5What is a WebSocket, and why not normal HTTP?

With HTTP, the browser has to ask the server for updates again and again. A WebSocket is a single connection that stays open, so the server can push updates instantly. I used Socket.IO, which uses WebSockets and adds automatic reconnection and rooms.

Q6How is the code executed? Is it safe?

The server copies the room's files into a temporary folder and runs them as a separate process, for example python3 main.py, or g++ and then the program. Limits: 10 seconds of run time, 200 KB of output, and the whole process group is killed when time runs out. The temporary folder is deleted afterwards.

It is fine for a classroom with trusted users, but it is not a full sandbox. For a public product I would run each program inside a Docker container with no network and limited memory. That's my main future improvement.

Q7How are passwords stored?

As bcrypt hashes, never as plain text. bcrypt is slow on purpose and adds a random salt, so even if someone stole the database, they could not easily recover the passwords. Login state is a signed JWT in an httpOnly cookie that expires after 30 days.

Q8Where is the data stored? Why not MySQL or MongoDB?

In a JSON file (data/db.json) for users, rooms and chat, and a binary Yjs file per room for the code. For a project of this size, it avoids installing and configuring a database server, and the app runs anywhere Node.js is installed. Writes are atomic, so a crash can't corrupt the file. For thousands of users I would move to a database such as PostgreSQL or MongoDB.

Q9What happens if someone's internet disconnects?

The status pill changes to “Reconnecting…”. They can keep typing. When the connection returns, Socket.IO reconnects, the browser and server exchange what each is missing, and Yjs merges the offline edits with everyone else's. Nothing is lost.

Q10How does the public link work if the app runs on your laptop?

I use a Cloudflare Tunnel. A small program, cloudflared, opens an outgoing connection from my laptop to Cloudflare, and Cloudflare gives me a temporary https://….trycloudflare.com address. Visitors connect to Cloudflare, which forwards the traffic to my laptop. It works only while my laptop and the command are running.

Q11How many users can join one room?

There is no fixed limit in the code. Yjs updates are very small, so a room with 10–20 people works smoothly on a laptop. The practical limits are the laptop's internet speed and running code, since only one program runs per room at a time.

Q12Which languages can it run, and why does Java not work here?

JavaScript (Node.js), Python 3, C, C++17 and Ruby. Java support is built in, but this laptop has no Java runtime installed. The server checks at startup and shows ✔ or ✘ for each language. Installing a JDK enables it with no code changes.

Q13How is this different from tools like Google Docs, Replit or VS Code Live Share?

Google Docs is not made for code: it has no syntax highlighting and can't run anything. Replit and Live Share are large commercial products that need accounts with those companies or an installed editor. Cody Vibes is lightweight, open, and self-hosted. You run it yourself, it works in any browser including phones, and I built and understand every part of it.

Q14What was the most difficult part?

Keeping everyone's text the same when people type at the same moment, and handling reconnections. My first idea of sending the whole file would lose edits, so I learned about CRDTs and used Yjs. Another challenge was running code safely: I added time limits, output limits, and killing the whole process group so infinite loops can't hang the server.

Q15What would you add next?

Running code in Docker containers for security. Voice or video chat inside rooms. Read-only “viewer” roles for teachers. Folders in the file tree. Version history using Yjs snapshots. Hosting on a cloud server so the link is permanent.

If something breaks during the demo

The link doesn't open
The tunnel stops when the Terminal closes or the laptop sleeps. Run npm run share again and use the new link. Stay calm and say it takes 10 seconds.
No internet in the classroom
Run npm start instead and open http://localhost:3000. Use an incognito window as the second user, side by side on the projector. Every feature still works.
Teacher's phone can't join
Use your own phone, or an incognito window on the laptop, as the second user. The collaboration still shows clearly.
Asked to run Java
Explain that Java support is built in but needs a JDK on the machine. Show Python or C++ instead.
A program runs forever
Click Stop, or wait: it is killed automatically after 10 seconds. You can turn this into a point: “there's a time limit so one bad loop can't freeze the server.”
Everything fails
Keep a 2-minute screen recording of the demo on your laptop and phone as a last resort. Record it the day before.
